# Transcript viewer admission and allocation review

This is the implementation boundary for ADR0051 B, not a provider/context or transport limit change. Review uses `application/conversions.rs::to_protocol_transcript_entry`, `tools.rs::{ToolInput::presentation_text,ToolResult::summary,ToolOutput::summary}`, `tools/hosted_web.rs`, canonical validators, and `persistence/backend/local_command.rs`.

## Delivered text

- User/assistant text: at most128KiB; direct pass-through. Image summaries are separate metadata; this work does not load image bytes or invent missing tool output.
- Tool-call path: path text,64KiB Bash command, bounded IPython cell, bounded search query, or a fixed task-count description. No hidden tool arguments are newly exposed. All fit the512KiB canonical payload envelope.
- Tool-result summaries: bounded data strings occur at most once. Read/directory/search/legacy editing are short summaries; legacy command output remains clipped by its existing4096byte-per-stream assembler. Current Bash includes both64KiB streams; IPython aggregate output is64KiB. Hosted search includes16KiB answer, at most10 titles≤512bytes/URLs≤4096bytes and fixed receipt metadata. Task output includes at most3 reports≤32KiB, bounded names/model metadata, and at most24 web receipts per child. Each receipt's rendered fixed fields fit256bytes; child header fits512bytes. Error envelopes are closed labels below1KiB. The512KiB serialized payload plus64KiB of generously bounded generated labels/numbers dominates every summary; it is still below1MiB. This upper-bound proof does not pretend every maximum can occur simultaneously.
- Local commands: command64KiB plus stdout64KiB plus stderr64KiB, with fixed status/optional i32/u16 metadata. Client-generated envelope is below128bytes even for Interrupted/Some(-2147483648)/Some(65535).
- Client tool-call/result labels also fit128bytes. Charge128bytes in addition to the carried strings for these formatted cases before allocation. Plain user/assistant text needs no such envelope reserve.

Admission uses checked sums and a single1MiB source ceiling, shared by the representation and viewer budget module. It rejects an impossible DTO with an existing bounded local error, not a clipped success. No remote field controls these constants. Preserve all valid delivered text, including controls that are deliberately rendered inert by the shared sanitizer.

## Window and allocation policy

The historical64-entry and live128-entry maxima remain. Additionally cap the sum of conservatively assembled source bytes at1MiB per window, before formatting/sanitization. This admits the largest standalone entry and, under four-space tab expansion, caps ordinary visible text at the old128×32KiB=4MiB maximum; the prototype's exceptional Unicode-escape policy and allocator capacity are separately allowed for below. This replaces the earlier unaccepted16MiB sanitized-window proposal with explicit units and derivation.

The constructor bounds source1MiB, sanitized temporary4MiB, final length6MiB. Across a window, final String capacities are less than12 times charged source (geometric growth bounded by twice final length or initial sanitized allocation). Range/metric counts are bounded by source newline count/128 plus at most six times source bytes/1920 plus a constant per entry: each closed part is forced by128 newlines or nearly2048scalars; an ordinary grapheme contains at most128bytes, escaped scalar units at most10bytes. Thus range vectors and viewport metrics remain separately bounded, including their vector growth. Avoid duplicating full strings or retaining all rendered Line/Span values. Keep the old window while constructing a replacement: two windows, one raw window and one constructor scratch remain bounded; existing IPC frames/queues, session/run metadata and the separate128KiB transient source buffer retain their independent bounds. This is not a measured total-process RSS promise.

When a fetched one-entry page would exceed the remaining byte budget, discard that lookahead and stop without advancing any installed cursor or entry/run list. The previous page's direction cursor still points to the unconsumed entry. Check fixed snapshot/session/event/active-run identity before accepting pages; preserve the opposite cursor from the first admitted page. Test both directions and exact equality at the budget. No fabricated cursor or canonical part entry.

On live capacity pressure, freeze the contiguous existing window, preserve its older cursor and mark newer output. Request the existing fresh latest snapshot automatically only while following latest; a reader scrolled into history keeps that frozen window until explicit navigation to newer/latest. Do not drain a prefix then erase its cursor. While deferred, discard subsequent presentation text/deltas rather than join a disjoint suffix. The existing gap-free subscription restart installs events after the fresh snapshot. Command/transient completion bookkeeping still occurs. Existing readonly query reconnect behavior is unchanged; no provider/tool retry is added.

## Render and streaming

Flatten entry identity plus width-independent part index for layout. Each paragraph gets at most one bounded part plus short first-header/last-footer labels. Build layout metrics when dirty/width changes and materialize only visible parts, not all line/span trees. Keep canonical entry indexes for last-run outcome attachment. Strip exactly the structural trailing newline from a non-final part when converting it to lines: the next part supplies the next row; preserve final deliberate empty lines. A non-newline split is an explicit soft display break, not data mutation. Part-local scroll fitsu16 by construction; do not saturate a huge block offset.

Rebuild streaming presentation from its complete bounded raw prefix after each accepted delta, so an escape/control string spanning deltas is not reinterpreted at a chunk boundary. Once128KiB preview admission fails, freeze that contiguous prefix permanently, explain preview pause and await the complete committed DTO. This does not cancel generation. Preserve refusal/run identity and remove/replace the transient on commit/terminal state. Explain oversized-grapheme scalar escaping visibly; retain small SafeText for labels/dialogs.

## Mechanical preparation

Move existing SessionView, PresentedTranscriptEntry and TransientAssistant definitions/implementations from app.rs into app/transcript.rs before functional work. Keep type/field visibility equivalent: old pub(super) at app becomes pub(crate) in the child; old private members used by parent become pub(super). Keep bodies unchanged, import parent helpers, then format/check/test before inference. This is a concrete ownership extraction to avoid repeatedly editing a2000line module, not a new public library API. Functional changes remain separately reviewable against that frozen seed.
