# ADR 0030: Native provider and task bindings

## Status

Accepted for staged implementation. This completes the identity/dispatch prerequisite of ADRs [0019](0019-openai-subscription-authentication-and-hosted-search.md), [0028](0028-native-codex-responses-contract.md) and [0029](0029-provider-admission-and-data-use-policy.md). It does not authorize real sign-in, inference, retained-state migration, a release or merging the draft. Native model admission stays closed until the complete path and tests are in place.

## Decision before implementation

Use neutral application/persistence model-service types with Zen=1, Go=2, OpenAI ChatGPT=3. The OpenCode transport's own two-service type remains restricted to its two reviewed routes. No native request gets a fabricated OpenCode identity or key. Legacy SQL columns named `open_code_service` retain that spelling for compatibility, but their reviewed encoding becomes the neutral service encoding; no existing value, accepted fingerprint, transcript attribution, model/body projection or default-policy maintenance digest changes. Protocol DTOs remain separate from persistence records and provider wire objects.

A common reviewed model profile projects existing OpenCode manifest entries and the independently reviewed native GPT-5.5 entry. It is metadata, not a new transport/plugin/catalog abstraction. Native full Responses remains protocol revision 5, with explicit local-only output acceptance limits and unknown account-controlled data use. Never infer an entitlement or spending cap from selectable metadata. Native selection requires explicit owner intent; login and unavailable-catalog fallback cannot silently choose it.

Root acceptance checks the selected credential kind and captures its owner generation. Foreground/background compaction inherits that exact service/model/generation. Credential refresh retains identity generation, while replacement/removal invalidates later stale dispatch. Provider-specific errors distinguish missing ChatGPT login and required reauthentication without exposing account/token material or falling back to another provider.

Before a task batch's outer Dispatched fact commits, the storage worker resolves and atomically stores its exact reviewed model/service/protocol/limits, credential generation, current data-use sequence and source-bound digest. InheritParent retains the accepted parent identity. Explicit selections in the same credential kind retain the parent's generation rather than silently adopting a replacement account. A different credential kind captures its own current configured generation. Recheck at child dispatch; never reuse an unrelated parent counter or reread a changed model setting for an already bound batch. Identifiers locate evidence, not authority: bindings validate the exact parent/call/operation and immutable task input, and cannot be applied to another run or call.

The existing outer task ledger continues to supervise all child effects; it is not a separate resumable session or automatic child retry log. A migration epoch distinguishes historical dispatched tasks without these new facts from new tasks that must have them. Startup validates binding evidence before recovery and never replays a child/provider/tool effect. Deleting a session removes only its Morons-owned binding rows, never the selected directory.

Use one concrete dispatch wrapper around the two reviewed adapters and reuse the existing root/child/compaction loops and Responses projection. A native turn owns its private provider/turn registration for exactly one accepted root, child or compaction execution. Stable conversation identities remain distinct for roots, child indices and maintenance jobs; foreground compaction has a separate turn even inside a root. Native instructions come only from the pinned Morons core; guidance, skills, summaries and canonical input remain separate untrusted context. Keep only receipt-bound ephemeral continuation, never persist hidden reasoning or routing state.

The current server-owned data-use policy is checked before lease preparation and at dispatch admission. Admission remains serialized by the storage worker with policy changes; already admitted work cannot be recalled. Native execution receives the server-authorized policy, not IPC-supplied permission. Every prepared/dispatched failure, cancellation and lost acknowledgement retains the existing known-versus-uncertain lifecycle and fail-closed storage behavior. No automatic retry, redirect, unsupported output parameter, API-key fallback, new model dialect or alternate origin.

## Implemented contract

IPC 42 uses neutral ModelService/ModelSummary/ModelSelection DTOs and typed model-list/default operations. SQLite 30 explicitly rebuilds the eight affected service/failure tables, preserving column order, old values and indexes; it adds `provider_binding_epoch` and bounded indexed `task_model_bindings`. The binding digest covers the exact run/call/operation, service and credential kind, generation, model/protocol/limits, policy and dispatch sequence, plus the original task input bytes. It commits with the outer Dispatched fact. Validation checks source scope, policy chronology, same-kind parent generation, matching dispatch evidence and completed report disclosure, before recovery or after external data-version changes. Historical tasks before the migration epoch remain historical; no bindings or retries are invented for them.

The concrete ModelProviders wrapper shares the existing credential broker with login, owns private provider/turn registrations and selects only the reviewed adapters. OpenCode request/body lowering remains unchanged. Native foreground compaction receives a separate turn/conversation; background jobs retain their own identity and native credential checks. Coding-model selection is explicit, including when no OpenCode model is available. Native model metadata exposes local-only output enforcement and never claims a verified entitlement.

Missing native login has a provider-specific application error. Reauthentication is distinct run failure 13; credential-store errors use fixed classification and fail-closed supervision. Cancellation during native credential resolution stops the prepared run as Cancelled, not an internal/provider failure. No uncertain token or inference attempt is replayed. Synthetic regressions caught and repaired the old persisted-service decoder and old task-report service allowlist; only the reviewed third identity was added, not arbitrary labels.

## Qualification

Preserve old schema/acceptance/body golden tests. Add populated migration and corruption/rebinding/recovery tests, provider-local and cross-provider generation changes, policy changes at each dispatch surface, actual synthetic native root/tool/image/continuation and mixed-provider task/compaction runs, cancellation/drop/no replay, terminal-safe model disclosure and deliberate selection. Run full locked local gates and exact-head platform/security CI. Only then request owner browser sign-in and a separately approved bounded live budget; signed/native release qualification remains independent.
