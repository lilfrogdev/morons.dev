# ADR 0050: Closed runtime diagnostics and child correlation

## Status

Accepted before implementation, under the owner's opt-in diagnostics request and explicit Astra-direct implementation authority. Extends ADR0049 only; no inference, tool, persistence, model, capability, route, cancellation or retry contract changes. Historical failures remain historical and their missing subtypes are not reconstructed.

## Boundary and schema

Use the existing explicit foreground `morons-server --debug` sink only. Default starts no writer and emits no new records. Keep the32-record queue,512-record-attempt cap,1024-byte encoded-line cap, checked IDs and100ms best-effort shutdown. No file, environment switch, IPC/table/transcript/model-context field or UI addition. No raw text, arguments/results, field names/fingerprints, headers/bodies, paths, provider IDs, credential metadata, reasoning or parser/error sources. Native ADR0036 ordinary diagnostics remain unchanged. The obsolete test-only Responses raw-event collector may be removed together with its OpenCode-only printer; the separate native ResponseStage mechanism, native diagnostics, response validation and model matching are not changed. Diagnostic observations are not durable dispatch/commit/billing evidence.

Add a closed tagged local location: Root with local run ID, or Child with local session ID/task-call ID/one-based child index. IDs remain16-byte arrays; they never come from provider conversation or response identity. Child records correlate the existing independently allocated OpenCode diagnostic attempt ID, sampled before consuming dispatch. Native returns None, not a fabricated OpenCode ID. The Child receipt flag reflects the actual returned adapter result; a failed/cancelled response lacks a receipt, not necessarily service usage. Prepared-ID allocation is not dispatch; never invent completion on Drop.

Extend DebugEvent with Resource, Normalization and ChildTool records. Resource has only location and a closed resource category. Distinguish the nine existing PersistenceResourceLimit categories (Sessions, Runs, Context, Transcript, LogicalSequence, CredentialGeneration, CredentialMutations, ModelSelections, DataUsePolicies), root deadline, child provider-turn/context-estimate/context-budget/tool-budget/usage-overflow/final-output guards, and normalized-output or provider-request bounds where only that guard is known. Never serialize PersistenceError or its source text. Emit root terminal observations after the existing failure transaction commits; persistence failure still dominates and no failure result is fabricated.

Normalization has location, a closed validation stage and a resource-limit boolean. Stages distinguish catalog/call-count/duplicate-call-ID/argument-JSON/tool-field-set/tool-type/read-window/edit-bounds/path/unknown-tool/forbidden-child-tool/task-bounds, final-message missing/empty/multiple/tool-in-final/tool-turn-message, and output-byte bounds; Other covers a known unclassified guard without guessing. An internal typed scratch snapshot may be returned with the unchanged original Result. Do not reparse a rejected outcome, retry it or change accepted tool input. Pure canonical-history validation must not emit diagnostics about old entries. Pass correlation explicitly; no global/thread-local last-error slot or implicit cross-session span.

ChildTool has the Child location, child attempt and tool ordinal, a closed tool kind, an optional closed tool error category and optional numeric Bash exit code/signal. Project these scalars at the caller; logging APIs never accept full ToolInput/ToolResult/ToolOutput or arbitrary strings. Tool kind covers the fixed MVP names plus Legacy/Other, never an echoed unknown name. Tool error names mirror existing closed ToolErrorKind variants; WebSearchUncertain discards its nested detail here (existing web diagnosis remains intact). Ok ToolResult with nonzero Bash exit is not command success. A record describes a returned tool result, not rollback, completed external effects or a replay invitation. Missing records and dropped queues remain unknown.

## Integration and tests

Convert/remove legacy extra OpenCode, normalization and tool-schema stderr/fingerprint diagnostics so the extra diagnostics obey opt-in even in Rust debug builds. Preserve ordinary fatal service errors and ADR0036 native diagnostics. Use the same parsers/transport/loops and original error ordering; no duplicate decoder or bypass. Shared parser helpers may carry a small typed diagnostic through validation, while existing canonical wrappers remain silent and behavior-compatible.

Test exact categories and unchanged Results; known versus unknown receipts; child/attempt separation; maximum locator/ordinal serialization within the existing byte limit; optional Bash exit/signal without output leakage; silent canonical validation; default silence versus explicit activation; cancelled/provider/normalization/resource/tool-error paths and no replay. Six previously independently qualified transport tests are deliberately adopted as repeatable unit regressions, not run-specific QA scripts or reports. Run frozen full formatting/check/debug+release Clippy/tests/build/dependency gates before the separately scoped one-shot Go probe. This decision does not qualify live reliability or the separate Daybreak fix.
