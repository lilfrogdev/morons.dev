# ADR 0045: Closed hosted-web failure diagnostics

## Status and evidence

Accepted before implementation. One owner-approved Astra-led live search ended Uncertain. The complete Astra response and outer search binding are durable, but the web executor discarded its dispatch error. No HTTP status, returned model, parser guard, response body or search usage was collected. The cause remains unknown. This decision neither reconstructs that response nor authorizes another request.

## Decision

Retain two closed, code-owned enums: the search execution/validation stage and the existing provider-error category. Track a stage within one owned search attempt; update it before a guard, never from a remote name/value. Map existing ProviderError variants exhaustively to fixed categories. No arbitrary strings, raw HTTP status text, headers/bodies, event names, queries, URLs, account claims, credentials, parser sources or reasoning enter diagnostics. Success and dropped futures do not manufacture diagnostic results. The stage identifies where validation stopped, not account eligibility or the ultimate cause.

When the owned executor returns an error after entering PreparedSearch execution, preserve its existing conservative uncertainty classification and attach these enums to a distinct canonical `WebSearchUncertain` tool error. This server-owned record is independent of provider wire objects and protocol DTOs. The root or outer task remains Uncertain; it never becomes successful or retryable. A child forwards its closed web failure through the drained outer task. Draining siblings must not overwrite an already observed web failure with a generic cancellation or join error; storage failure still dominates and stops controlled execution. All existing before-dispatch credential, policy and storage behavior remains unchanged.

Only a bound web call or task from a newly accepted tool-catalog/limits12 run may record this error. Historical catalogs and generic Uncertain payload bytes remain valid and unchanged; recovery cannot invent a missing stage. Validate this restriction both on completion and on reading/rebuilding persisted evidence. Tool catalog/limits advance to12 to distinguish the new result vocabulary; fixed model-tool request schemas, coding protocol, limits, search contract1 and schema32 remain unchanged. Older servers must fail closed on unsupported accepted tool versions. No IPC shape change: ordinary tool-result summaries already carry bounded terminal-safe text, and will display the static stage/category with explicit uncertainty/no-retry wording. Do not reuse the native-coding diagnostic event or suggest that the successfully completed main-model response failed.

No response guard, event allowlist, identity check, source/usage/citation bound, deadline, routing, credential custody, dispatch admission, no-replay rule or main/subagent selection is relaxed. No Brave fallback, hidden memory, new log capture, background probe or credential import is added. The retained QA home stays stopped and untouched during implementation.

## Qualification

Synthetic tests must verify precise closed stages for HTTP rejection/framing, timeout/cancellation, SSE/envelope/lifecycle/sequence, model identity, output reconciliation, usage, actions and citations. Verify successful results remain equal, original ProviderError variants remain equal, failure cannot rearm an attempt, and malicious strings never enter Debug/Display/canonical diagnostics. Exercise real mock HTTP through root and mixed Astra→Go GLM child ownership, durable Uncertain result and visible summary, no next parent request, recovery and strict serialization/version/scope checks. Preserve historical generic Uncertain bytes and require no real credentials or inference. Run all locked gates and exact-head CI in a focused dependent PR. A subsequent fresh live probe requires separate bounded owner authority; never replay the retained uncertain operation.
