# ADR 0038: Native completed output items

## Status and evidence

Accepted before implementation, 2026-09-08. A separately approved fresh GPT-5.5 validation prompt on22fb963 passed HTTP/header/SSE handling but failed at fixed `completed-identity`. That guard covers response identity/object/status and output-array size; no raw response was collected, so the exact predicate and earlier samples' causes remain unknown. No request is retried.

Independent public evidence supports a specific compatibility gap: official Codex459a79eb85400af759e9220c7bafb4429ae07516 (`codex-rs/codex-api/src/sse/responses.rs`) emits semantic OutputItemDone from `response.output_item.done`, then uses `response.completed` for terminal identity/usage. [Hermes5678](https://github.com/NousResearch/hermes-agent/issues/5678) (2026-04-07, closed) reports an empty terminal output array despite streamed output; [PicoClaw2674](https://github.com/sipeed/picoclaw/issues/2674) (2026-04-26, closed) specifically reports native complete items delivered through output_item.done. These independent reports and the implementation are evidence, not proof of Morons' live payload or license to adopt permissive fixtures, concatenate deltas into fabricated outcomes, accept unfinished function calls, or relax identity/usage. Historical model names in reports do not expand admission.

## Decision and boundary

Add a concrete native constructor for the existing Responses decoder. OpenCode retains the original constructor and behavior. Only native collects `response.output_item.done` while Active, after existing strict JSON/envelope/event/sequence validation. Require output_index within128, one completed item per index, and a complete contiguous zero-based index range at terminal completion. The per-response cache is bounded by the existing128-item,1MiB record-byte and100,000 event-node ceilings, cumulatively charged using original done-event byte/node counts. It has no external identifier, persistence or Debug/raw diagnostic channel; malformed/failed/cancelled/dropped streams discard it.

The successful terminal event must still provide the existing exact response/model/object/status, an array-valued output (missing/null remain rejected), valid bounded usage and normal clean stream termination. If the terminal array is empty, require nonempty cached complete items and pass them through the SAME complete message/reasoning/function validation and delta consistency checks previously used on terminal output. Deltas, added events, end markers or partial function arguments alone cannot complete a result. If both sources exist, normalize both with existing validators and require equality, including IDs, phases, text/refusal, tool names/argument bytes and opaque reasoning; ignored wire extensions are not authority. Empty output with no complete items remains an error. Duplicate/gapped/excessive items, conflicting terminal output, later text/argument deltas for closed items, unknown output types, missing required item data and invalid usage/identity all reject. No tool call executes or canonical assistant output commits before the complete outcome passes all guards.

The cache belongs to one decoder/HTTP response, not a reusable turn or session. Existing receipt fingerprints and exact provider/turn/model/generation/source bindings govern any admitted reasoning continuation. Native HTTP media handling follows ADR0037. No request replay, route/model fallback, alias/access assertion, Lite mode, model expansion, remote metadata authority, diagnostic raw data, limit increase, dependency or durable memory is introduced. Shared source is factored only to reuse the same output validation; OpenCode outcomes and historical request/context/digest/receipt bytes remain unchanged. Native full Responses5/IPC44/SQLite30/credential formats are unchanged.

## Qualification

Reproduce failure before adding item collection. Compare native empty-tail and full-tail outcomes with the old complete-output path; test text/refusal/reasoning/functions and delta reconciliation, aggregate byte/node/item bounds, duplicates/gaps, incomplete sources, source conflict, post-done deltas, identity/model/usage failures and isolation across responses. Real native HTTP/image/tool/receipt integration must exercise item events followed by empty terminal arrays, with no replay or credential change. Existing OpenCode acceptance/rejection tests and all locked local/platform/security gates remain required. Preserve the three failed live samples outside Git. This repairs an independently reproducible completion-source incompatibility, not a proven live cause; another owner-approved fresh sample is required for live qualification.
