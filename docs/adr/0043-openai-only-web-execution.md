# ADR 0043: OpenAI-only web execution

## Status

Accepted before implementation. The owner explicitly removed Brave support and requested OpenAI-only web search, while targeting Astra/Daybreak for main coding and GLM-5.3-Flash for child coding. This supersedes the backend-choice/default plans in ADRs 0041–0042: no Brave executor, credential environment lookup, selector or fallback remains. Historical Brave transcripts still decode without being rewritten as OpenAI results. The dedicated search model remains reviewed GPT-5.5/hosted contract1, not the selected main or child coding model; this does not select or fall back to GPT-5.5 for coding. Changing that separate search model needs reviewed interoperability evidence.

## Ownership and dispatch

Keep the single `web_search(query)` tool. Only the bounded query and fixed instructions go to the existing one-shot hosted-search adapter. No parent transcript, files, skills, local functions or browser profile is attached. OpenAI search requires the server's ChatGPT credential even when a coding model uses OpenCode. No new provider credential source is added.

After ADR0044's independent SQLite31 task-deletion repair, SQLite32 adds source-bound web identities for newly dispatched root web tools and task batches. The sole storage worker commits them atomically with the existing outer Dispatched fact. Bind the exact run/call/operation, fixed service/model/contract/limits, native credential generation, policy sequence and original input bytes. Native roots retain their accepted generation. A native child binding also retains that identity; otherwise capture the configured native generation at outer dispatch. A task may record generation0 when no native identity exists: other child tools remain usable, but later login cannot silently grant that batch a new account. A root web tool requires a configured identity. Each child inherits its outer task's web binding, not mutable settings or its unrelated OpenCode generation.

The outer task ledger continues to own child effects, as in ADR0030, rather than creating resumable child sessions or an external-effect replay log. Child search attempt identities are source-separated and include the child index and unique tool ordinal. Before each HTTP dispatch, reload/validate the exact active outer binding and admit the current native search data-use policy through the storage worker after credential preparation. Restrictive settings reject unknown native policy. This admission is serialized with policy mutations; later changes cannot recall a request, refund usage or prove remote cancellation.

Startup and external-data-version validation check a migration epoch, required binding coverage, bounded indexed pages, source digests, matching Dispatched facts and policy chronology. Old evidence stays old; interrupted work terminates through existing recovery and is never replayed. Session deletion removes only Morons-owned binding records through explicit storage-worker statements before their owning calls/runs, never its selected directory. Do not add cascading trigger paths or raise SQLite trigger-depth limits. No credential bytes, account claims or hidden reasoning enter SQLite.

## Results, uncertainty and presentation

Add a distinct bounded canonical OpenAI web result, retaining the historical Brave result shape for reading only. Disclose fixed search identity/contract, completed action counts, answer, typed citations and provider-reported token usage separately from root/child coding usage. Child reports preserve a bounded separate list of successful web receipts even if later child work fails. Token subsets and action counts are not prices, spending caps or savings claims.

A missing login or policy rejection fails before inference with fixed errors. Storage integrity or worker failure drains/stops controlled work rather than returning model-authored success. A dispatched transport failure or cancellation with no complete outcome is uncertain; never manufacture citations, usage or a completed search from progress. Root uncertainty uses the existing outer tool/run lifecycle; child search uncertainty cancels/drains the batch and makes the outer task uncertain, preventing another parent request or child retry. Recovery of an interrupted bound root search or outer task remains uncertain. Cancelled/interrupted tasks may not deliver completed child receipts; their absence is not evidence of zero usage. Error text must describe external/service effects rather than imply only local file changes.

Render the normalized answer, source titles and literal HTTP(S) URLs through existing terminal-safe text cells, with bounded output. No automatic URL opening, OSC8/OSC52, clipboard access or personal-browser automation is added. Owners may deliberately use a displayed URL through their terminal/browser; an in-app navigation helper is not required for search admission. URLs remain untrusted locators, not authorization or factual-proof tokens. IPC transport shape remains unchanged unless implementation needs a new DTO; internal tool catalog/limits advance to11 while historical accepted bytes and context digests remain valid.

## Qualification

Before implementation, preserve synthetic fixtures proving the previous Brave request cannot meet OpenAI request/privacy/credential semantics. Test root and mixed-provider child search, binding scope/generation changes/missing credentials, policy changes, cancellation/deadline/no replay, persistence corruption and restart, legacy result compatibility, bounded usage/citations and safe visible presentation. Run all locked local gates and exact-head platform/security checks in focused PRs, then a bounded live application search with public verifiable citations. No direct unmanaged-token probe, uncertain replay, retained-home migration or release is implied by synthetic success. The native main/subagent preferences remain separate from this web-search increment.
