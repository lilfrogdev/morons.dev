# ADR 0036: Secret-free native protocol failure diagnostics

## Status and evidence

Accepted before implementation. The owner prioritizes the unresolved native protocol failure over further model work. The original GPT-5.5 request failed with generic ProviderProtocol failure7; no provider body was collected and the exact guard is unknown. Queue loss was independently repaired, not established as the provider failure's cause. Public Codex fixtures use permissive/minimal event envelopes, but those fixtures alone do not establish which real response differed or justify relaxing Morons' validation.

## Decision

Instrument existing validation with a closed code-owned stage only: headers, header framing, content type, redirect, body bounds, routing state, body framing, SSE framing, JSON, event bounds, event envelope, event kind, sequence field, sequence ordering, lifecycle, response identity, response model, text delta, refusal delta, argument delta, completed envelope, completed identity, usage, assistant message, reasoning, function call, output consistency, termination. No raw event/field name, value, parser source, provider body, header, model alias, hidden reasoning, token/account/claim/scope/expiry, request text or callback data is diagnostic material.

Keep the original ProviderError and all run/operation failure classifications, including uncertainty, unchanged. Store at most one optional stage on the private ephemeral native turn; clear it on dispatch and success. Shared Responses validation records only an enum independently of its existing test-only raw diagnostic helper. Required sequence field decoding is distinguished from ordering, and usage decoding is performed at the usage guard so malformed usage fields and invalid arithmetic share the correct closed category; acceptance rules are unchanged. Native transport copies that enum on a protocol error; cancellation, timeout, credential/policy/entitlement/provider rejection do not become protocol failures. No new acceptance branch, retry, route/model fallback, alias acceptance, lifetime/deadline/resource relaxation or external request is introduced.

After a native ROOT provider-protocol failure transaction commits, publish a small ephemeral session diagnostic containing exact session/run IDs and an independent protocol stage enum. Do not publish if persistence fails. It is neither assistant output nor a canonical transcript entry. No SQLite migration, hidden memory, diagnostic query endpoint or historical failure rewrite. Child/foreground/background outcomes retain their existing behavior; this increment does not add diagnostic data to their summaries/tool results or persist new run metadata.

Use a separate bounded64-element broadcast for these tiny diagnostics. Slow consumers disconnect on diagnostic lag; writes retain the existing5s bound. The connection first catches up durable events, then forwards its one pending diagnostic only for the same session's latest terminal native ProviderProtocol run and with no later active run. This avoids racing a diagnostic ahead of its committed terminal event. Other sessions, stale runs and new subscriptions missing the event do not obtain replay/history. Unlike the durable cursor stream, diagnostic delivery is explicitly ephemeral: disconnect/restart/switching can lose it; a missing reason never authorizes retry.

IPC44 adds the closed enum and a cursor-free `SessionNativeResponseDiagnostic` event. DTOs remain independent of provider types through an explicit conversion. Old/new clients must negotiate matching versions; SQLite30 and credential formats remain unchanged. Client subscription validation requires the matching preceding terminal native protocol-failure event and rejects wrong-session/run/duplicate/foreign diagnostic events without advancing its durable cursor. The terminal shows fixed code-owned text and the exact local run locator, scoped to the displayed failed run. A delayed notice must not imply that a newer run failed; active work suppresses it. It cannot change a draft, model, run result or retry an operation. Returning to a session or restarting can lose this status; generic durable failure evidence remains.

## Qualification

Tests must distinguish header/sequence/model/usage/output/termination guards with synthetic hostile markers that never appear in diagnostics; keep all old accept/reject tests and ProviderError values. Verify failed/cancelled/dropped turns are not reusable, no extra request, no credential replacement, closed wire enums/no detail fields and version mismatch. Exercise actual synthetic HTTP root failure through post-commit publication and authenticated subscription framing, durable-event ordering, session/run scoping, slow/duplicate consumers, and terminal-safe status without transcript/draft/model mutation. Preserve full locked local/platform/security gates. Stop the old server with its matching client before using IPC44 binaries. A new owner-approved single small probe is a separate budget; this instrumentation does not claim the original failure is fixed or authorize a replay.
