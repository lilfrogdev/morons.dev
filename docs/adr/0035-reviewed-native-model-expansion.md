# ADR 0035: Reviewed native model expansion

## Status

Accepted for staged implementation, 2026-09-07, before code. The owner requests broad model support, starting with Astra, Sol, Luna, Terra and Daybreak Blue. This decision extends ADRs0028/0030 with those five exact models, not automatic future/retired-model admission. Synthetic/platform qualification and owner-authorized live usage remain separate. The earlier GPT-5.5 live protocol rejection remains causally unclassified; this does not claim to repair that unknown guard.

## Evidence and corrected premise

Official Codex source at `459a79eb85400af759e9220c7bafb4429ae07516`, `models-manager/models.json`, lists `gpt-6-astra`, `gpt-5.6-sol`, `gpt-5.6-luna`, `gpt-5.6-terra`, `gpt-daybreak-blue-latest` with text/image input, text output, function tools, reasoning and medium effort. Daybreak Blue is hidden in that upstream listing. Public [Codex models](https://developers.openai.com/codex/models) names the four general coding models. [Daybreak Blue](https://developers.openai.com/api/docs/models/gpt-daybreak-blue-latest) requires separate approval/provisioning; API aliases/access do not prove native subscription availability.

The initial proposed prerequisite was Responses Lite because official Codex sets `use_responses_lite:true` for these entries. That is a client-selected dialect, NOT proof that the backend requires Lite exclusively. Before implementation, owner-requested inspection of non-secret Pi model configuration supplied a plain Daybreak Blue model entry under the normal Codex provider, without endpoint/header/authentication/access-program overrides. Configuration is reference evidence, not imported authority or a live-success claim; no authentication store was read or used.

Reviewed Pi AI0.84.2 distribution source `dist/api/openai-codex-responses.js` (SHA256 `cf537f03ee3da7a7edbe28e447642a50d34e6a32a4f8aef599b5a496394e3999`) constructs full Responses with explicit model, top-level instructions/tools, stream/store/cache/reasoning fields on the fixed native backend. `dist/providers/openai-codex.js` pins the native route; `dist/providers/data/openai-codex.json` lists the5.6 family on that same adapter. Astra's model/capabilities come from the reviewed official Codex manifest, not a claim that it ships in Pi's static catalog. The generic Pi request constructor does not branch into Lite by model name. This supports starting on the existing concrete full-Responses contract instead of adding a speculative mandatory dialect prerequisite. No Pi code is imported as a dependency. Pi's attribution, automatic transport fallback/retry, grammar/deferred/hosted tools, pricing, large limits and permissive remote-catalog admission are not adopted.

## Decision

Keep native full Responses revision5 and existing GPT-5.5 bytes. Add the five exact IDs to the server-owned manifest on the same concrete reviewed full-Responses route and request shape. Shared profile/application/root/task/compaction bindings already carry exact selected model/revision and provider-local credential generation. Add end-to-end synthetic coverage for those entries; do not merely expose names in the picker. Login never selects a model, explicit defaults/child settings remain owner choices, and failed/unavailable models do not fall back. Daybreak's display explicitly discloses approval is required; no fabricated program assertion, extra endpoint or copied eligibility/credential is sent. Do not silently rewrite Blue to Sol based on API alias metadata. Exact returned-model validation remains.

All six entries retain96k input/32k output LOCAL acceptance bounds, text/images, strict local function tools, medium reasoning/low verbosity and unknown/account-controlled training/retention. A selectable model is not verified entitlement, favorable policy, a spending cap or universal interoperability. No max_output_tokens, API-key billing fallback, remote memory, previous_response_id, dynamic capability, grammar tool, Responses Lite header or namespace change. Both restrictive data-use settings still reject unknown metadata independently. Provider rejections remain failures; no uncertain operation is retried.

There is no new IPC shape/version, persistence schema, credential format, request dialect or historical receipt/digest. OpenCode Zen/Go remain distinct and unchanged. Later broader model coverage requires exact model/protocol/capability review and tests, not a promise that every model from every service already works. Retired native5.4/mini and arbitrary future IDs remain rejected. Lite may be implemented later if independently justified; it is not an assumed prerequisite for this increment.

## Qualification

Add six-model admission/policy/credential/default/picker tests, exact body/header/no-cap contracts and unsupported-model checks, actual loopback root text/image/tool/receipt flows for every new model, and shared child/compaction/reopen bindings using new selections. Preserve full5.5/OpenCode golden and persistence tests. Run locked fmt/check/Clippy debug+release/workspace tests/deny/build and exact-head platform/security checks before further owner sampling. Real subscription requests, Daybreak access, billing, refresh and signed/native release qualification are not implied. No additional inference without a new explicit budget and complete draft/model/directory verification before Enter. Diagnostic improvements must expose only closed code-owned stages, never raw provider bodies, parser sources, headers, hidden reasoning or credential data.
